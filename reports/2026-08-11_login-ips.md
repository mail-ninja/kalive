## Kort svar

**Antall forskjellige remote-IP-er i innloggingsloggen: 0**

Alle registrerte logins er **lokal grafisk sesjon** (`:0` / `tty7` via LightDM).  
Det finnes **ingen** SSH-/nettverks-login med IP i wtmp/journal for denne perioden.

«Bare min IP er riktig» — i login-loggen finnes det **ingen** fremmede login-IP-er å sjekke mot. Det er bra.

## wtmp / `last` (28. jul – 11. aug 2026)

| Host-felt | Betydning | Antall rader (ca.) |
|-----------|-----------|---------------------|
| `:0` | Lokal X11-display (konsoll) | alle void/lightdm-sesjoner |
| (tom) | f.eks. postgres/void uten tty ved install | 2–3 rader 28. jul |

Brukere som har «logget inn»:

- **void** — lokale desktop-sesjoner
- **lightdm** — greeter (forventet)
- **postgres** — én kort post 28. jul (pakke/install, ikke remote)

Ingen `pts/*` fra SSH, ingen IP i host-kolonnen.

## Journal (auth)

| Sjekk | Resultat |
|-------|----------|
| `sshd` journal | tom / ingen entries |
| `Accepted password/publickey` | **0** |
| `Failed password` / `Invalid user` | **0** |
| `session opened` med `rhost=` IP | **0** |
| SSH lytter nå | nei (port 22 ikke i listen) |

Sessioner som finnes: lightdm, void (lokal), sudo, cron, pkexec — alt lokalt.

## IPer som *finnes* i journal generelt (IKKE logins)

Journal inneholder mange IPer fra **nettverkstrafikk** (DHCP, mDNS, WiFi-naboer, Docker). Det er **ikke** innlogginger. Eksempler:

| IP | Typisk rolle |
|----|----------------|
| 192.168.10.1 | gateway (høy frekvens) |
| 192.168.25.203 / 192.168.155.203 / 192.168.6.79 | denne maskinens LAN-adresser over tid (hotspot/nett byttes) |
| 224.0.0.251 / 239.255.255.250 | mDNS/SSDP multicast |
| 172.17/18/19.x | Docker |
| Enkelte offentlige IPer (1 treff) | utgående/DNS/app — ikke auth (se `public_ip_context.txt`) |

## Begrensninger

- `/var/log/auth.log` finnes ikke (journald only)
- `/var/log/btmp` (failed logins) ikke lesbar som vanlig user med wtmpdb
- wtmp starter **2026-07-28** — eldre historikk finnes ikke her

## Konklusjon

Innloggingsloggen viser **kun lokal tilgang**.  
**0 remote login-IP-er.** Ingen avvik å «kaste ut» basert på login-IP.

For fortsatt overvåking: hold SSH av, eller fail2ban hvis SSH skrus på.
